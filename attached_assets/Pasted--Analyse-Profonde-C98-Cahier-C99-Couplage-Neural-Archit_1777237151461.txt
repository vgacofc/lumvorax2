## PARTIE 1 — Le module nx48_neuro_coupler : architecture décryptée

### Pourquoi couplage et non substitution

```
NX48 (existant) : réseau heuristique qui guide le mining
  → Apprend les patterns de nonces prometteurs
  → Contrôle delta_nonce, exploration_bias, T_hot/T_cold
  → 12 871 cycles d'apprentissage = mémoire accumulée

Si substitution : tout l'apprentissage NX48 est perdu
  → delta_nonce revient à 0 → redémarrage à zéro
  → Perte des 12 871 itérations de convergence

Couplage : NX48 garde 100% de ses décisions
  Les neurones Izhikevich reçoivent les features NX48
  Ils produisent un signal de modulation ∈ [-1, +1]
  NX48 peut l'ignorer OU en tenir compte à hauteur de ±15%
```

### La architecture 3 couches biologiquement fondée

```
Couche 1 : 8 neurones Izhikevich Regular Spiking

  1 neurone par feature NX48 :
  F1 = best_leading_zeros → neurone 1
  F2 = hashrate_mhs       → neurone 2
  F3 = nx48_loss          → neurone 3
  F4 = near_miss_count    → neurone 4
  F5 = delta_nonce        → neurone 5
  F6 = exploration_bias   → neurone 6
  F7 = T_hot              → neurone 7
  F8 = T_cold             → neurone 8

  Gain de courant : feature × 30 pA
  → Feature élevée = neurone très actif = taux de spike élevé

Couche 2 : STDP full-mesh 56 synapses

  Chaque neurone connecté à tous les autres : 8×7 = 56 paires
  Règle Song-Miller-Abbott 2000 :
  → Si neurone A spike avant B (pré→post) : w_AB augmente
  → Si neurone A spike après B (post→pré) : w_AB diminue
  → Asymétrie 1.05× (A_+ > A_-) pour stabilité poids

  Après apprentissage : les features corrélées renforcent leurs synapses
  → Features covariantes (hashrate + leading zeros) → w fort entre neurones 1-2
  → Features anti-corrélées (loss vs leading zeros) → w faible

Couche 3 : Signal de modulation

  mean_rate_hz = taux moyen de spikes sur fenêtre 50ms
  Si rate < 20 Hz → signal < 0 → NX48 reçoit signal d'exploration
  Si rate > 20 Hz → signal > 0 → NX48 reçoit signal d'exploitation
  20 Hz = régime RS sain = neutre (homéostasie biologique)

  Analogie :
  Le cerveau humain module l'exploration via la dopamine.
  Ici : near-miss BTC = injection +50 pA = pic de "récompense"
  → Le réseau biologique apprend que les near-miss sont positifs
  → Il modifie ses poids synaptiques pour favoriser l'exploitation locale
```

### Les 7 tests unitaires : analyse de chaque cas

```
T3 — Features hautes → mean_rate > 5 Hz
  Valeur observée : 63.4 Hz (72 spikes en 1 seconde simulée)
  Attendu pour RS sous courant fort : 20-80 Hz ✅
  
  Si features = [0.95, 0.95, ...] → courant = 0.95 × 30 = 28.5 pA
  Pour Izhikevich RS : 28 pA → ~60 Hz (cohérent avec la littérature Izhikevich 2003) ✅

T5 — STDP modifie les poids après 1000 steps
```

```
    → VORAX : limiter les circuits à depth_useful layers

[6] checksum_norm = 0.8291
    → FNV1a-64 du vecteur normalisé = identifiant forensique unique
    → Permet de détecter si les paramètres hardware ont changé entre deux runs

[7] n_qubits/256 = 0.6094
    → 156/256 = 0.609 → fraction de la capacité d'un backend 256Q hypothétique
    → Méta-métrique pour comparer backends de tailles différentes
```

## PARTIE 5 — Cahier C99 : analyse des priorités

### P0.1 — Brancher nx48_coupler_step : le patch analysé

```c
/* Patch C99 dans nx48_btc_controller.c ligne ~683 */
static nx48_coupler_t *g_coupler = NULL;
if (cfg->use_neural_coupler && !g_coupler) {
    g_coupler = nx48_coupler_create(run_id, 0.1);
}
if (g_coupler) {
    int near_miss = (best_leading_zeros >= 20) ? 1 : 0;
    double mod = nx48_coupler_step(g_coupler, features, near_miss);
    s->exploration_bias = clamp(
        s->exploration_bias * (1.0 + 0.15 * mod), 0.05, 0.95
    );
}
```

**Analyse du clamp(0.05, 0.95) :**
```
Sans clamp :
  Si mod = +1 (exploitation max) et exploration_bias = 0.95 :
  Nouvelle valeur = 0.95 × 1.15 = 1.0925 → hors [0,1] → undefined behavior

Avec clamp(0.05, 0.95) :
  Jamais complètement exploratoire (0.05 minimum)
  Jamais complètement exploitant (0.95 maximum)
  → Zone de sécurité de 5% de chaque côté ✅

Le facteur 0.15 (±15% d'influence) :
  C'est un choix conservateur.
  Si le coupleur suggère exploration max (+1) :
  bias augmente de 15% max → ne bouleverse pas NX48
  → NX48 garde ~85% de son comportement natif ✅
```

### P1.1 — DMRG Trotter-1 : pourquoi c'est critique

```
C97 a mesuré S(π)/N = 0.77-0.81 pour N=16-96 sur IBM.

Test DMRG Trotter-1 :
  Simuler exactement le même circuit (RXX(0.30) + RZZ(0.30)) sur Aer
  Calculer S(π)/N du résultat exact (sans bruit)

  Cas 1 : S(π)/N_DMRG ≈ 0.78-0.81 aussi
    → Le plateau est intrinsèque au circuit Trotter-1
    → IBM le reproduit fidèlement → signal physiquement réel ✅

  Cas 2 : S(π)/N_DMRG < 0.78 (ex : 0.65)
    → Le bruit IBM AJOUTE du signal AFM artificiellement
    → C'est un artefact hardware → résultat non publiable ⚠️

  Cas 3 : S(π)/N_DMRG > 0.81 (ex : 0.90)
    → IBM SOUS-ESTIME le signal (bruit dégrade S(π))
    → ZNE pas assez agressif → augmenter resilience en C100

Ce test prend 1h de calcul classique et 0 quota IBM.
```

## PARTIE 6 — Questions expertes C98/C99

### 🔴 Critiques

**Q1 — La récompense dopaminergique +50 pA : biologique ou ad hoc ?**

```
Le choix de +50 pA lors d'un near-miss (≥20 LZ) :
  Dans le cerveau : dopamine = récompense de prédiction d'erreur
  Libérée quand l'événement est meilleur qu'attendu
  Modélisée par injection de courant dans Izhikevich : biologiquement plausible

Mais le seuil near_miss = 20 LZ est arbitraire.
  20 LZ = P(aléatoire) = 1/2^20 ≈ 10^{-6}
  Ce n'est pas calibré sur la distribution réelle des near-miss NX48

Recommandation C99 :
  Définir near_miss_threshold dynamiquement :
  threshold = percentile_90(leading_zeros_history)
  → +50 pA seulement si leading_zeros > 90e percentile des derniers 100 essais
  → Signal de récompense plus biologiquement réaliste
  → Évite la sur-stimulation si NX48 produit régulièrement 20+ LZ
```

**Q2 — A/B testing NX48 : le protocole C99 est-il suffisamment rigoureux ?**

```
Protocole proposé :
  Run A : NX48 seul, 30 min
  Run B : NX48 + coupleur, 30 min

Problèmes potentiels :
  1. L'ordre des runs importe : si Run A en premier,
     le premier run "chauffe" le GPU et Run B bénéficie d'un état thermique différent
     → Contre-balancer : faire A-B-A-B (alterné) ou simultané (2 processus)

  2. 30 min = 1 run = haute variance statistique
     best_leading_zeros en 30 min peut varier de 5-10 bits selon la chance
     → Minimum 5 runs par condition pour test t-test fiable

  3. NX48 charge son état depuis btc_nx48_last.csv :
     Si Run B démarre après Run A, NX48 hérite de l'état de Run A
     → Biais : NX48+coupleur semble meilleur car il part d'un état déjà optimisé
     → Solution : réinitialiser btc_nx48_last.csv avec un état neutre avant chaque run

Protocole rigoureux recommandé :
  5 paires (A,B) avec ordre randomisé, état NX48 réinitialisé, 30 min chacun
  Durée totale : 10 × 30 min = 5h Ubuntu
  Test statistique : Wilcoxon signed-rank (non-paramétrique, adapté aux petits N)
```

**Q3 — OpenMM Na_v 1.5 : l'estimation 9 000 atomes est-elle correcte ?**

```
PDB 6AGF = structure cristallographique Na_v 1.5 humain :
  Protéine seule : ~3 800 acides aminés × ~10 atomes/AA = 38 000 atomes
  En réalité : les canaux ioniques sont des homo/hétérotétramères
  
  Na_v 1.5 = pseudo-hétérotétramère (1 seule sous-unité α ~ 2016 AA)
  + sous-unités β1-β4 optionnelles
  
  Système solvaté SPC/E + CHARMM36 lipide bicouche :
  Protéine : ~15 000 atomes
  Lipides (POPC bicouche) : ~30 000 atomes
  Eau + ions : ~50 000 atomes
  TOTAL : ~95 000 atomes

  9 000 atomes = monomère pore seul (domaine transmembranaire uniquement)
  C'est une approximation agressive mais faisable en 1 ns NPT

  Simulation 1 ns NPT sur Ubuntu RTX (GPU OpenCL) :
  Temps estimé : ~2h avec OpenMM + CUDA (si GPU dédié)
  Avec Intel UHD 620 (pas de CUDA) : ~20-48h → trop long !
  
  Alternative : utiliser CPU seul OpenMM (~10h pour 1 ns) ou réduire à 100 ps
```
