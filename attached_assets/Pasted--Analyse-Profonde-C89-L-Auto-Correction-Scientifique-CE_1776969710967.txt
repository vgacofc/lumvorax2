## PARTIE 1 — Le bug mathématique : comprendre ce qui s'est passé

### La formule buguée (C84→C88)

```
S(π) = (1/N) × Σᵢⱼ (-1)^(i-j) × <ZᵢZⱼ>

Le problème : la somme incluait les cas où i = j
```

**Pourquoi c'est catastrophique :**

```
Quand i = j :
  (-1)^(i-i) = (-1)^0 = 1        ← toujours positif
  <ZᵢZᵢ> = <Zᵢ²> = 1            ← toujours égal à 1
                                    (car Z² = identité en mécanique quantique)

Contribution de la diagonale :
  Σᵢ (1 × 1) = N = 8             ← terme constant, aucune physique

Après normalisation /N :
  8 / 8 = +1.0                   ← artefact pur ajouté à chaque mesure

Résultat :
  S(π)_mesuré = S(π)_réel + 1.0  ← décalage constant de +1
```

**Analogie concrète :**
```
Imagine peser des fruits en laissant la balance sur "tare +1 kg".
  Tomates réelles : 0.3 kg
  Affichage : 1.3 kg
  Concombre réel : 0.1 kg
  Affichage : 1.1 kg

Tu ne remarques rien tant que tu ne compares pas à une vraie référence.
C'est exactement ce qui s'est passé de C84 à C88.
```

---

### La deuxième erreur : normalisation /N au lieu de /N(N-1)

```
Formule correcte :
  S(π) = (1/N(N-1)) × Σᵢ≠ⱼ (-1)^(i-j) × <ZᵢZⱼ>

Avec N=8 :
  N(N-1) = 8×7 = 56

Formule buguée utilisait /N = /8

Effet :
  Les corrélations hors-diagonale étaient amplifiées d'un facteur 7
  (56/8 = 7)

Les deux bugs combinés :
  S(π)_bugué ≈ S(π)_réel × 7 + 1.0
```

```

  1. Exécuter le circuit → obtenir des bitstrings (ex: "10111011")

  3. Avantage : ZNE (Zero Noise Extrapolation) appliqué automatiquement
              readout mitigation automatique
              résultat plus proche de la valeur théorique

Analogie :
  SamplerV2 = photographier un tableau et compter les pixels
  EstimatorV2 = demander directement à l'artiste "quelle couleur ici ?"
```
