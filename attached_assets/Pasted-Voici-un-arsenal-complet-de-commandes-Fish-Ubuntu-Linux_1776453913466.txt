Voici un arsenal complet de commandes Fish (Ubuntu/Linux) pour faire une inspection forensique précise des processus, RAM, CPU, threads et anomalies — adapté exactement à ton cas (processus caché qui bouffe ~15 GB RAM + contention CPU).

🔎 1. Vue globale système (RAM / CPU immédiat)
# RAM + swap (lecture rapide)
free -h

# Stat mémoire détaillée (kernel)
cat /proc/meminfo | less

# Charge CPU temps réel
uptimea

# Top interactif (processus triés CPU)
top

👉 Variante plus lisible :

htop
🧠 2. Trouver QUI consomme la RAM (CRITIQUE dans ton cas)
# Top processus par RAM
ps aux --sort=-%mem | head -20

👉 Version plus précise avec RSS réel :

ps -eo pid,ppid,cmd,%mem,%cpu,rss --sort=-rss | head -20

👉 Conversion RSS → MB lisible :

ps -eo pid,cmd,rss --sort=-rss | awk '{printf "%-8s %-50s %.2f MB\n", $1, $2, $3/1024}' | head -20
🧬 3. Analyse profonde d’un processus suspect

Remplace PID :

# Infos complètes
cat /proc/PID/status

# Mémoire détaillée (maps)
cat /proc/PID/smaps | less

# Résumé mémoire
pmap -x PID | tail -n 20

# Threads (important pour ton mining)
ps -T -p PID
🧵 4. Voir les threads (détecter contention mutex / scaling foireux)
# Threads + CPU par thread
top -H -p PID

👉 ou :

ps -eLf | grep PID
⚠️ 5. Trouver les processus "fantômes" ou oubliés (run BTC anciens)
# Tous les process liés à ton projet
ps aux | grep -i lumvorax

# Ou BTC
ps aux | grep -i btc

# Ou mining
ps aux | grep -i mine

👉 nettoyage rapide :

kill -9 PID
🔍 6. Qui consomme 15GB ? (détection automatique)
ps -eo pid,cmd,rss --sort=-rss | awk '$3 > 1000000 {print $0}'

👉 (1000000 KB ≈ 1GB)

🧱 7. Mémoire kernel / cache (important pour ton cas RAM 1.5GB)
# Cache Linux
cat /proc/meminfo | grep -E "Cached|Buffers"

# Drop cache (⚠️ root)
sudo sync
sudo sysctl -w vm.drop_caches=3

pstree -p

👉 super utile pour voir :

anciens runs BTC
processus enfants oubliés
watchdogs
🔥 9. Détection contention CPU / saturation
