* lecture via `/proc/self/mem`

# 2. Là où tu sur-interprètes (important)

## 2.1 ❌ “bit-level memory tracing”

Tu écris :

> “bit-par-bit”

Mais en réalité :

* granularité réelle = **page (4KB)** ou sampling
* checksum = **résumé**, pas état bit exact

👉 Correction stricte :

> ❗ tu fais du **state hashing + snapshot mémoire**, pas du bit tracking continu

---

## 2.2 ❌ `/proc/self/mem = mémoire physique`

Tu écris :

> “lecture de la mémoire physique”

C’est incorrect.

👉 `/proc/self/mem` =

* mémoire virtuelle du process
* traduite via MMU

Pas :

* RAM brute
* ni mémoire kernel

---

## 2.3 ❌ “traçage exhaustif”

Limites réelles :

* pages non résidentes ignorées
* race conditions possibles
* pas atomique

👉 donc :

> ❗ ce n’est pas exhaustif au sens strict

---

## 2.4 ❌ Quantum claim

Tu as bien corrigé toi-même :

> observables uniquement

👉 Donc :

✔️ OK :

* counts
* distributions
* métriques (S(π), entropy)

❌ PAS OK :

* état quantique
* superposition interne

# 3. Bugs critiques identifiés (très importants)

## 3.1 🔴 Fichiers .lum non alignés

> reste 10 / 47 / 26 bytes

👉 Ça casse :

* parsing
* reproductibilité
* intégrité

### Cause probable :

```c
fwrite(header)  // ≠ multiple de 64
puis
fwrite(lum_t)
```

---

## 3.2 🔴 Timestamps incohérents

> > 1e18 ns

👉 problème possible :

* overflow
* mauvaise base (epoch vs monotonic)

---

## 3.3 🔴 Encodage double incorrect

```c
memcpy(&lum.position_x, &value, sizeof(double));
```

👉 MAIS :

```c
position_x = int32_t
sizeof(double) = 8 bytes
```

❗ écriture hors champ → corruption mémoire

---

## 3.4 🔴 Checksum XOR faible

XOR32 :

* collisions triviales
* pas fiable pour validation forte

---

## 3.5 🔴 fflush systématique

```c
fflush(w->fp);
```

👉 énorme coût I/O

* détruit le buffering
* limite scaling

# 5. Solutions concrètes (priorité C117)

## 🔴 PRIORITÉ 1 — intégrité format

### Fix alignement

```c
// option 1 : header multiple de 64
typedef struct {
    char magic[4];
    uint32_t version;
    uint8_t padding[56];
} lum_header_t; // = 64 bytes
```

OU

```c
// option 2 : pad automatique
size_t rem = filesize % 64;
if (rem != 0) write(padding, 64 - rem);
```

---

## 🔴 PRIORITÉ 2 — corriger corruption double

Remplacer :

```c
memcpy(&lum.position_x, &value, sizeof(double));
```

Par :

```c
double v = value;
memcpy(lum.padding, &v, sizeof(double));
```

OU définir :

```c
union {
    double f64;
    uint8_t bytes[8];
} lum_value_t;
```

---

## 🔴 PRIORITÉ 3 — checksum robuste

Remplacer XOR32 par :

* CRC32 (rapide)
* ou xxHash (idéal)

Exemple :

```c
uint32_t checksum = XXH32(page_buf, 4096, seed);
```

---

## 🔴 PRIORITÉ 4 — timestamps corrects

Utiliser :

```c
clock_gettime(CLOCK_MONOTONIC_RAW, &ts);
```

et stocker :

```c
uint64_t ns = ts.tv_sec * 1e9 + ts.tv_nsec;
```

---

## 🔴 PRIORITÉ 5 — I/O optimisé

Remplacer :

```c
fflush() chaque entrée
```

Par :

* buffer circulaire
* flush toutes les 1000 entrées

---

## 🔴 PRIORITÉ 6 — preuve scientifique forte

Ajouter :

### Test manquant critique

* écrire pattern mémoire connu
* modifier 1 bit
* vérifier LUM détecte EXACTEMENT ce bit

👉 ça validera ton claim “bit-level” (localement)
