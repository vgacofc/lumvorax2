## Analyse experte — Cycle C88 (VORAX/SPATIAL → IBM + BTC)

### Résumé exécutif

Le cycle C88 présente **trois résultats structurels** :

1. **Succès d’ingénierie logicielle réel** (fix GPU BTC + pipeline VORAX fonctionnel)
2. **Résultat quantique IBM cohérent expérimentalement mais probablement biaisé au niveau de l’observable S(π)**
3. **Architecture VORAX/SPATIAL crédible comme transformateur de circuit, mais pas encore validée physiquement au sens Hubbard**

Le point critique est simple :
➡️ **le signal S(π) > 1.0 est très probablement un artefact de définition / normalisation ou d’observable.**

---

# 1. Analyse physique — S(π) = 1.0229 (IBM ibm_fez)

### 1.1 Incohérence principale

Le rapport indique :

* S(π) ≈ **1.0229**
* Comparaison ED/Hubbard 8 sites attendue : **~0.6 – 0.85 max**
* Observé : dépassement du "plafond physique attendu"

### Problème structurel probable

Dans le code  :

```python
S += ((-1) ** ((i - j) % 2)) * np.mean(z[:, i] * z[:, j])
return float(S / n)
```

### Problème identifié

Deux points critiques :

#### (A) Normalisation incorrecte

* Division par `n` au lieu de `n²` ou `(n(n-1))`
* Cela **amplifie artificiellement la magnitude de S(π)**

#### (B) Inclusion des termes diagonaux i=j

* `z_i * z_i = 1` → contribution constante positive
* Ajoute un offset systématique ~+1

➡️ Conclusion :

> S(π) > 1 n’est pas une signature physique robuste ici, mais un **artefact structurel de définition de l’observable**

---

# 2. Analyse du circuit VORAX (HTS 8Q)

### 2.1 Points solides

Le pipeline est réellement innovant :

* Fuse → génère corrélations locales (CX + H)
* Cycle → propagation via SWAP chains
* Split → injection de corrélations non locales
* Spatial → layout aware hardware topology

➡️ Ceci est **une vraie architecture de compilation quantique structurée**, pas un simple VQE brickwork.

---

### 2.2 Point critique physique

Le circuit :

* depth_phys = 256
* 185 portes 2Q
* 8 qubits seulement

➡️ Ratio extrêmement élevé :

> ~23 portes 2Q / qubit → régime fortement bruité IBM

Donc :

* augmentation S(π) peut venir de **noise-induced correlations**
* ou **bias de transpilation + routing SWAP-heavy**

---

### 2.3 Hypothèse alternative importante

Le comportement observé (S(π) élevé + entropie ~max) correspond typiquement à :

* état quasi-chaotique Haar-like
* mais biaisé par observable structuré (-1)^(i-j)

➡️ donc :
**signal AFM apparent ≠ état AFM réel**

---

# 3. Analyse du code IBM runner

## 3.1 Problème majeur : observable S(π)

### Erreur conceptuelle

Le code suppose :

> S(π) = simple corrélation bitstring-based

Mais en Hubbard réel :

* S(π) = structure factor spin operator
* nécessite <Z_i Z_j> sur état physique, pas post-processing bitstring brut

➡️ ici on approxime un opérateur quantique complexe par une statistique classique de bitstrings mesurés.

---

## 3.2 Problème de mesure

```python
bits = np.array([1 - 2 * int(b) for b in bs[::-1]])
```

* mapping Z basis correct
* MAIS dépend entièrement du basis measurement only
* pas de rotation basis → observable limité à Z-only

➡️ donc :

> on ne mesure qu’un sous-espace de l’Hamiltonien Hubbard

---

## 3.3 SPATIAL_DISPLACE

Heuristique :

* basée sur degré du coupling_map uniquement
* ignore :

  * CX error rates
  * T1/T2 calibration map
  * readout asymmetry

➡️ donc layout = **topologique, pas physique**

---

## 3.4 VORAX_COMPRESS

Présent mais :

* jamais utilisé dans pipeline C88
* mesure + reset casse l’unité du circuit

➡️ fonction structurellement inactive dans ce cycle
